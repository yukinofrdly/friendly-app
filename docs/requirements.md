# FRIENDLY 業務基幹システム 要件定義書

**プロジェクト名**: FRIENDLY (仮称)
**バージョン**: v0.1 (MVP要件)
**最終更新**: 2026-05-15
**作成者**: FRIENDLY株式会社 / 幸野裕史

---

## 1. プロジェクト概要

### 1.1 目的

中小企業の「売上だけでなく、原価・粗利まで見える経営」を実現する、AI 活用業務基幹システム。エクセル運用に起因する以下の課題を解決する。

- 原価が別ファイル/別シートに散在し、案件別の粗利が見えない
- 受注前に粗利率の判定ができず、「赤字受注」が発生する
- 請求書発行・入金消込・督促が月末に集中する手作業
- 売上・粗利数字がリアルタイムに把握できず、経営判断が遅れる

### 1.2 ターゲット

- 従業員 10～100 名規模の中小企業
- 業種は問わない（建設・士業・卸売・製造・サービス業 等）
- 経営者が「数字をリアルタイムに見たい」と感じている組織

### 1.3 提供形態

- マルチテナント SaaS
- ブラウザベース、モバイル対応
- freee / マネーフォワードクラウド と API 連携

### 1.4 スコープ外（v0.1 では実装しない）

- 給与計算・勤怠管理（連携のみ将来検討）
- 在庫管理
- 多言語対応（日本語のみ）
- iOS/Android ネイティブアプリ

### 2.2 ユースケース

#### UC-01: 案件登録から受注、粗利アラート

```
登場人物: 田中(営業)、佐藤(経理)、社長
前提: 田中がアプリにログイン済み

1. 田中が「+ 新規案件」ボタンを押す
2. 顧客名「山田商店」、案件名「リプレース」、売上見込¥4,500,000 を入力
3. 原価明細タブで人件費¥1,500,000 / 外注費¥2,200,000 / 材料費¥400,000 を入力
4. システムが自動で粗利率 8.9% を計算、画面に赤色で表示
5. AI が「粗利率 8.9% は会社目標(20%) を大きく下回ります」とアラート表示
6. AI 推奨: ①外注先の見直し ②受注価格 +¥350K 交渉 ③辞退
7. 田中がアラートを上司に共有(@メンションまたは Slack 連携)
8. 上司が AI の提案を採用、外注先を変更して原価¥3,400,000 へ
9. 粗利率 24.4% に改善、ステージを「商談中」→「提案中」へ移動
```

#### UC-02: 受注確定 → 請求書自動発行 → 入金消込

```
登場人物: 田中(営業)、佐藤(経理)
前提: 案件「○○商事」が「受注」ステージに移動

1. 田中が案件詳細から「請求書を発行」ボタンを押す
2. システムが見積情報・顧客情報を引き継ぎ、請求書 No (連番) を自動採番
3. インボイス制度準拠の PDF が生成、顧客の請求先メールへ自動送付
4. システムは請求書ステータスを「発行済」に
5. 一週間後、銀行 API から入金データが取り込まれ、自動マッチング
6. 佐藤が消込結果を確認、ステータスが「入金済」に変わる
7. 仕訳データが freee に自動同期
```

#### UC-03: 月次の経営確認

```
登場人物: 社長
前提: 月末締めの翌営業日

1. 社長がダッシュボードを開く
2. KPI ボードに「当月売上 ¥48.2M / 粗利 ¥10.3M / 粗利率 21.4%」表示
3. 案件別粗利ランキング、粗利アラート案件、未収案件が一画面で確認可能
4. 「粗利率」グラフをクリックし、案件別ドリルダウン
5. 山田商店案件の粗利が想定より下振れしていることを発見
6. 担当者にコメントを残して原因確認を依頼
```

## 3. 非機能要件

### 3.1 パフォーマンス

- ページ初回ロード: 3 秒以内 (3G 回線)
- 主要画面遷移: 1 秒以内
- 1 万件規模の案件一覧でも操作レスポンス劣化なし (ページネーション、仮想スクロール)
- 同時接続: テナントあたり 100 ユーザーまでを想定

### 3.2 可用性

- SLA 99.5% (商用ローンチ後)
- 計画停止は事前通知必須
- バックアップ: 日次 (PITR 7 日間)

### 3.3 セキュリティ

- 通信は TLS 1.2 以上必須
- パスワードは bcrypt または argon2 でハッシュ化
- 認証セッションは JWT または httpOnly Cookie
- マルチテナントのデータ分離は **Row Level Security (RLS) を必須**
- 入力値は全てバリデーション (Zod / Valibot)
- SQL インジェクション・XSS・CSRF 対策
- 監査ログは全テナントの操作を記録 (将来要件)

### 3.4 法令・規制対応

- インボイス制度 (適格請求書等保存方式) に準拠した請求書フォーマット
- 電子帳簿保存法 (改正電帳法) 要件を満たす保存・検索機能
- 個人情報保護法に準拠したデータ管理

### 3.5 スケーラビリティ

- 水平スケール可能なアーキテクチャ
- DB は将来の Read Replica 追加を想定
- ファイルストレージは S3 互換 (将来のリージョン分散も視野)

### 3.6 アクセシビリティ

- 主要画面で WCAG 2.1 Level A 準拠を目指す
- キーボード操作のみで主要機能が完結
- フォントサイズはユーザー側で拡大可能

### 3.7 国際化 (i18n)

- v0.1 は日本語のみ
- 将来の多言語対応を見据え、文字列は外部リソース化 (i18n フレームワーク利用)
- 通貨は JPY 固定 (将来はテナント設定で切替可能に)

## 5. 業務フロー (主要パターン)

### 5.1 案件→受注→請求→入金 フロー

```
[リード登録]
   ↓
[商談中] ─→ 原価入力 ─→ 粗利計算 ─→ AI粗利アラート判定
   ↓
[提案中] ─→ 見積作成・送付
   ↓
[受注 or 失注]
   ↓ (受注の場合)
[請求書発行] (自動 or 手動)
   ↓
[請求書送付]
   ↓
[入金待ち] ─→ 期限超過なら自動督促
   ↓
[入金消込] (銀行API or 手動)
   ↓
[完了] ─→ 仕訳同期 (freee/MF)
```

### 5.2 督促フロー (自動)

```
発行 +0日: 請求書送付
発行 +7日: リマインドメール (AI生成、トーン: 丁寧)
発行 +30日: 督促メール (AI生成、トーン: 警告)
発行 +45日: エスカレーション → 担当営業に通知
```

## 10. 用語集

| 用語 | 説明 |
|---|---|
| **テナント** | 1つの組織 (会社) のデータ単位。マルチテナント SaaS の単位 |
| **案件** | 営業活動の1単位。リードから完了までを管理 |
| **粗利** | 売上 − 原価。本システムの最重要指標 |
| **粗利率** | 粗利 ÷ 売上 × 100 (%) |
| **原価明細** | 1案件に紐づく人件費・外注費・材料費等のコスト内訳 |
| **AI 粗利アラート** | 粗利率が目標水準を下回る案件を AI が自動検知し警告 |
| **エイジング** | 売掛金の滞留期間別残高 (0-30日、31-60日、...) |
| **消込** | 入金データと請求書を紐付け、未収から入金済へ更新する作業 |
| **インボイス制度** | 適格請求書等保存方式。2023/10 開始の消費税法改正 |
| **電帳法** | 電子帳簿保存法。電子取引データの保存要件を定める |
| **RLS** | Row Level Security。行単位のアクセス制御。マルチテナントで必須 |
